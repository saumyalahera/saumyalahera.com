Real-Time Neural Garment Rendering on iOS

A camera-to-screen pipeline that detects body landmarks in real time and renders a dynamic virtual shirt using a custom TensorFlow-like ML API and a Metal shader-based rendering engine.

One-line summary

“The goal wasn’t just running ML on-device — it was maintaining deterministic per-frame latency so the shirt stays stable and believable at interactive frame rates.”

Key outcomes

  • Live body landmark detection driving garment placement
  • GPU-friendly preprocessing + inference acceleration via MPS
  • Shader-based fabric lighting and visual effects
  • Designed to scale across iPhone device capabilities

What it does

User experience

  • User stands in front of the camera
  • Body landmarks update continuously
  • Virtual shirt anchors to the torso with smoothing
  • Shaders add fabric shading, lighting, and stylized effects

Why it matters

  • Real-time correctness: stable placement during motion
  • Performance: maintain responsiveness under frame budget
  • Quality: believable visuals without heavy compute cost

Why a custom ML framework (vs TensorFlow Lite)

System requirement

This is a real-time engine: camera → preprocessing → inference → pose/mesh mapping → rendering, repeated every frame. The primary constraint is deterministic latency, not model execution alone.

  • Minimize memory copies/conversions in the camera loop
  • Control scheduling and buffering so rendering never stalls
  • Keep the inference path GPU-friendly

Design decision

  • Built a TensorFlow-like API to keep model usage consistent
  • Decoupled API from backend so implementations can evolve
  • Optimized iOS data paths (CVPixelBuffer/Metal textures)
  • Enabled device-based tuning and graceful degradation

TFLite can run models, but this project needed iOS-first control of memory, scheduling, and GPU integration.

Architecture

Input

  • AVFoundation capture
  • YUV → RGB via Metal
  • Frame timing + buffering

ML layer

  • Tensor abstraction + TF-like API
  • MPS-accelerated ops where applicable
  • Device-aware configuration

Rendering

  • Garment mesh transform from landmarks
  • Metal render pipeline
  • Shader effects (lighting/fabric)

Device compatibility (all iPhones)

Strategy

  • Capability detection (GPU family / OS constraints)
  • Dynamic resolution scaling under load
  • Graceful fallback paths for older devices
  • Thermal-aware adjustments (quality vs stability)

What I measured

  • End-to-end frame latency (camera → screen)
  • Inference time distribution (p50/p95)
  • Dropped frames and backpressure events
  • Thermal impact over sustained sessions

Roadblocks & solutions

Frame drops

  • Decoupled inference from render loop
  • Buffered frames; avoided blocking the UI
  • Reduced copies by aligning tensor/texture formats

Unnatural warping

  • Temporal smoothing on landmarks
  • Constraint-based mesh deformation
  • Stabilization during rapid motion

Collaboration

  • Defined garment behavior and visual targets with design
  • Aligned ML conversion/optimization with model stakeholders
  • Device matrix testing and edge case validation with QA

Execution

Status

  • Working prototype on physical iPhones
  • Stable, real-time overlay with GPU-accelerated pipeline
  • Framework designed to support additional garments/effects

Next extensions

  • Occlusion improvements (arms over torso)
  • Model variants for faster/older devices
  • More fabric materials and lighting models
  • Integration pathways (commerce, try-on flows)
